# Analyse: PARA vs. eigenes Second-Brain-Modell

Stand: 2026-11-14. Entscheidung des Owners: beim eigenen Modell bleiben; den PARA-Kern (Aktionabilitaet) in geringen Schritten uebernehmen.

## 1. Kernunterschied (Organisationsprinzip)

- Eigenes Modell: sortiert nach Thema + Jahr (quellengetrieben: Quelle -> Eingang -> Einordnung -> Notiz/Thema).
- PARA: sortiert nach Aktionabilitaet, vier Kategorien:
  - P - Projects (aktive Vorhaben, Ziel + Deadline)
  - A - Areas (dauerhafte Verantwortung, kein Ende)
  - R - Resources (Referenz/Interesse)
  - A - Archives (inaktiv/erledigt)

Der grosse Unterschied: PARA fragt "wie handlungsrelevant ist das jetzt?", das eigene Modell fragt "zu welchem Thema gehoert das?".

(Andere Modelle: Zettelkasten = Verlinkung, Johnny Decimal = Nummernstruktur. PARA ist hier der passendste Vergleichspunkt.)

## 2. Was im eigenen Modell schon abgedeckt ist

- Areas entspricht themen/ (Finanzen, Gesundheit, Versicherungen ...) - gut abgedeckt.
- Resources entspricht themen/ + dem Anlagen-Referenzwissen - gut abgedeckt.
- Archives entspricht der Jahres-Struktur (notizen/<jahr>/ + Drive "Jahr -> Thema") - abgedeckt, aber implizit (kein expliziter Archiv-Status).

## 3. Luecken - was fehlt und was es bringt

### Luecke 1 - "Projects" (aktive Vorhaben mit Ziel + Deadline): fehlt komplett
- Heute liegt Aktives verstreut in Themen + datierten Notizen; keine Sicht "woran arbeite ich gerade, naechster Schritt?".
- Vorteil: klare Projekt-Sicht + naechster Schritt je Vorhaben.
- Aufwand: mittel - projekte/-Konzept als Sicht ueber Notizen (kein neuer Drive-Ordner) + Status-Feld.
- Status: vorerst zurueckgestellt.

### Luecke 2 - Actionability-Markierung (aktiv vs. Referenz): fehlt
- Vorteil: Aktives springt ins Auge, Referenz stoert nicht.
- Aufwand: gering - Metadaten-Feld status (projekt/bereich/referenz/archiv) an Notizen; keine Ordner-Umbauten.
- Status: umgesetzt (Feld status in notiz-format.md dokumentiert).

### Luecke 3 - Einfache Top-Level-Orientierung: teilweise
- Vorteil: schnelle Orientierung fuer Owner und kuenftige Agenten.
- Aufwand: gering - Dashboard-/Uebersichtsseite.
- Status: umgesetzt (README-Dashboard).

### Luecke 4 - Areas vs. Resources trennen: teilweise
- Vorteil: klareres mentales Modell (Finanzen = Bereich, Anlagen-Wissen = Referenz).
- Aufwand: gering - themen.yaml um Feld art (bereich/referenz) ergaenzen.
- Status: umgesetzt (Feld art in themen.yaml; Anlagen = referenz).

## 4. Einschaetzung

- Hoher Nutzen, geringer Aufwand: Luecken 2-4 - PARA-Kern (Aktionabilitaet + Orientierung) ohne Struktur-Umbau.
- Mittlerer Nutzen, mittlerer Aufwand: Luecke 1 (Projects-Sicht) - groesster Alltagsmehrwert, eigenes Konzept.
- Nicht sinnvoll: kompletter PARA-Umbau (4 Ordner) - wuerde Drive-Ablage + ADRs umwerfen.
